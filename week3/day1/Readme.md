# Week 3 — Day 1: Filesystem Hierarchy + Core Navigation

## Theory: Linux Filesystem Hierarchy

Studied the core FHS directories and what each is used for:

| Path | What it holds | Security relevance |
|---|---|---|
| `/etc` | System & application config files | First place to check for misconfigs/credentials |
| `/var/log` | System & application logs | Primary forensics/SOC source |
| `/home` | Per-user home directories | User files, SSH keys, bash history — enumeration target |
| `/tmp` | Temporary files, world-writable | Common privilege escalation target |
| `/bin`, `/sbin` | Command binaries (general vs. root/admin) | `/sbin` = admin-only tools (fdisk, iptables) |
| `/proc` | Live, kernel-generated info on running processes | Auto-generated by the kernel — disappears when process ends |
| `/run` | Runtime state files (PID files, sockets) | Self-reported by processes for other programs to coordinate with |

**Key distinction learned:** `/proc` is created automatically by the kernel to track every running process. `/run` is written by a process itself, as a note for *other* processes to find — e.g. a PID file so `systemctl stop <service>` knows what to kill.

**Absolute vs. relative paths:**
- Absolute paths start from `/` — same string works from anywhere (e.g. `/etc/passwd`).
- Relative paths are resolved against the current directory (`pwd`) — the destination is fixed, but the string describing the route there changes depending on where you're standing.
- Scripts/cron jobs should use absolute paths since they have no fixed "current directory" context.

## Lab: Core Navigation Drill

Commands practiced: `cd`, `pwd`, `ls -la`, `find`, `grep -r`, `cat`, `less`, `head`, `tail -f`

**Navigation:**
```bash
cd /etc; pwd
cd ..; pwd
cd ~; pwd
cd -; pwd
```

**Exercise 1 — find all `.conf` files system-wide:**
```bash
find / -name "*.conf" 2>/dev/null
```
Returned 800+ results across the system — mostly tool/service configs (apache2, nginx, sqlmap, nikto, john, ettercap, responder, postgresql, samba, etc.). Confirmed `/home/kali` and config dirs populated correctly post-reinstall.

**Exercise 2 — grep for "root" in /etc/passwd:**
```bash
grep -r "root" /etc/passwd
```
Returned 2 lines — including a false positive: `nm-openvpn`'s line matched only because its home path contains `chroot`, which contains the substring "root". **Lesson: grep matches substrings, not concepts.**

**Fix — anchor to start of line:**
```bash
grep "^root:" /etc/passwd
```
Returned exactly 1 line — the real root entry only. `^` anchors the match to the beginning of the line, eliminating the `chroot` false match.

## Practice: Piping and Redirection

```bash
ps aux | grep ssh
```
Found `ssh-agent` running (client-side key holder), but **no `sshd` process** — meaning no SSH server was listening. Refined with:
```bash
ps aux | grep ssh | grep -v grep
```
to exclude grep's own self-match from the results.

**Verified with systemctl directly:**
```bash
sudo systemctl status ssh
```
Confirmed: `Active: inactive (dead)`, `disabled` at boot — SSH server installed but not running and not set to auto-start.

**Extracting fields with cut:**
```bash
cat /etc/passwd | cut -d: -f1
```
Listed all system usernames (root, daemon, sshd, postgres, redis, kali, mahesh, etc.) by splitting on `:` and printing field 1.

**Filtering + redirecting to a file:**
```bash
ls -la /etc | grep ".conf" > conf-files.txt
cat conf-files.txt
```
Saved filtered `.conf`-related entries (files, directories, and one symlink — `vconsole.conf -> default/keyboard`) into a local file.

## Deep Dive: OverTheWire Bandit — Levels 0–3

Connected via:
```bash
ssh bandit0@bandit.labs.overthewire.org -p 2220
```

| Level | Challenge | Technique used |
|---|---|---|
| 0 | Find password in a plain file | `ls`, `cat` |
| 1 | Filename is just `-` | `cat -- -` or `cat ./-` — `-` alone is read as "stdin," not a filename |
| 2 | Filename contains spaces | `cat "spaces in this filename"` — quotes preserve it as one argument |
| 3 | Filename hidden (dotfile) + leading/trailing dashes + spaces | `ls -la` to reveal hidden files; `ls -b` to reveal exact spacing; `cat -- "--spaces in this filename--"` combining the `--` and quoting fixes |

**Key lesson across all four:** the shell parses dashes as option flags and spaces as argument separators by default. `--` and quoting are the two core techniques to override that when filenames are deliberately unusual — a pattern that repeats constantly in real CTFs and engagements.
